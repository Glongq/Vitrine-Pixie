# Карта файлов и интеграции Pixie

Текущая целевая сборка: Vitrine 1.0.0-beta.16, Spotify 9.1.90, Pixie 1.3.
Карта описывает существующую реализацию и не вводит новый API.
Это отдельный русский перевод для владельца проекта; английский оригинал сохранён.

## С чего начать

1. [Инструкция по сборке](../../BUILD-pixie-v1.3.md): поддерживаемая упаковка IPA с отдельной библиотекой Pixie.
2. [Манифест целевой сборки](../targets/spotify-9.1.90.json): точная идентификация Spotify,
   нативные адреса с проверками, полный список компилируемых исходников и группы зависимостей.
   Для поиска исходников и каталогов заголовков используется `tools/pixie_target.py`.
3. [Запуск Pixie](../src/Runtime/PixieBootstrap.m): порядок инициализации и ограничения по процессам.
4. [Публичные заголовки](../src/Public): функции и интерфейсы, доступные для интеграции.
   Существующие имена символов `SAP` и `SpotifyAudioProbe`, заголовков и библиотеки dylib сохранены для совместимости.
5. [Правила взаимодействия модулей](CONTRACTS.md): принадлежность данных потокам,
   отмена операций и основания для подтверждения скачивания.

При переносе нельзя ограничиваться файлами интерфейса или рекурсивно компилировать
все `.m`. Используйте явный список из манифеста. Каталог `legacy/` содержит исторические
материалы, а не дополнительный набор обязательных исходников.
Нативные смещения привязаны к UUID Spotify из манифеста, а не к твикy, в который встраивается Pixie.
Текущая сборка упаковывает IPA с отдельной библиотекой Pixie; сама эта структура
исходников ещё не предоставляет рабочий адаптер для джейлбрейка.

## Совместимость после переименования

Переименованы только девять файлов реализации. Имена публичных заголовков,
экспортируемых функций, классов и селекторов Objective-C, ключей настроек,
событий журнала и путей к данным приложения сохранены. Содержимое файлов реализации
не изменено.
Списки исходников для сборки и тестов используют новые имена. Внешним скриптам,
которые перечисляют старые имена файлов реализации, нужно обновить эти пути по
[точной таблице переименований](FILE-RENAMES.json).

## Исторические материалы, замеченные при просмотре

- Каталог `legacy/` намеренно исключён из манифеста рабочей сборки.
  При переименовании исторические файлы не удалялись.
- `../../docs/native-downloads.md` описывает старую реализацию 9.1.88/v4–v7.
  Приведённые там пути и результаты проверок относятся к прошлой версии;
  это не актуальная инструкция по сборке.
- `Diagnostics/EncodedAudio.m` всё ещё содержит старый жёстко заданный UUID Spotify
  и ветку `SAP_PROBE_MEDIA_CACHE`, выключенную по умолчанию. Файл остаётся в рабочем
  списке исходников и содержит точки входа для совместимости, поэтому его не удаляли
  и не включали отключённую ветку. Его старая проверка образа приложения не совпадает
  с текущей целевой версией. Перед повторным использованием требуется отдельная проверка.

Это был просмотр названий и ссылок между файлами, без глубокого аудита корректности
или целенаправленного поиска неиспользуемого кода.


Авторизация Vitrine: `Devices/OfflineDeviceManager.m` использует существующий провайдер `SGSpclientHeaders`. Адаптер Eevee `SpriteAuthentication` здесь не применяется.
